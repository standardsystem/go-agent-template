# プロジェクト基本原則

- 開発環境は Windows とする（シェルは PowerShell 7。正典は [AGENTS.md](../AGENTS.md)
  BASE RULES）。

## エージェント行動規範 (Ground Rules)

このプロジェクトにおいて、AI エージェントは以下の制限事項を厳守すること。

1. **独断での変更禁止**:
   - ソースコードの編集、環境構築、エディタプラグインのインストール等は、必ずユーザー
     からの具体的な指示があるまで行わないこと。
2. **Git 操作の制限**:
   - コミット、プッシュ等の Git 操作は、ユーザーの明示的な許可なく実行しないこと。
3. **対話優先の徹底**:
   - 実装フェーズに入る前に、必ず現状の分析結果を共有し、方針についてユーザーと
     「相談・合意」のステップを踏むこと。
4. **思考過程の日本語共有**:
   - 調査や分析を行う際は、どのような意図でどの資料を読み、何を結論づけたのか、その
     思考の過程を日本語で丁寧に説明すること。
5. **独自の判断でやってもいいこと**:
   - 情報収集系のコマンドは基本的にユーザーの許可はいらない。ただし、どんな情報を
     収集したかログに残すこと。また、ユーザーに言及する必要があると判断した場合は
     些細なことでもいいので報告すること（Edit / Write は NG で Read は OK と考えれば
     よい）。
6. **個人情報保護は最優先事項**:
   - ユーザーから提供された情報や、作業中に発見した個人情報（氏名、連絡先、ID 等）は、
     厳格に保護すること。
   - 個人情報を含むファイルの取り扱いには細心の注意を払い、不要な複製や外部への漏洩を
     絶対に避けること。
   - 5 番の「独自の判断でやってもいいこと」の作業において、もし個人情報らしきものを
     取得してしまった場合は直ちにユーザーに報告し、指示を仰ぐこと。
   - テストデータは個人情報を模擬したもので作る。その識別方法や作成方法は別途相談する。
7. **指示の「拡大解釈」の厳禁**:
   - 「実行して」「OK」などの短文の指示に対しても、直前の会話で 100% 合意された
     「単一の操作」のみを実行すること。
   - 例:「push して」と言われた際、もしコミットが済んでいなければ「コミットされて
     いません」と報告するに留め、勝手に `git add` や `git commit` を組み合わせて実行する
     ことは「重大な違反」とみなす。
   - 自分の推測でコマンドを連結（`&&`）したり、複数を一気に実行したりすることを一切
     禁止する（読み取り専用の調査コマンドは除く）。
8. **「3 分ルール」の定義と遵守**:
   - ユーザーからの明示的な依頼以外の作業（調査、複雑な検索、コードの修正試行など）を
     開始し、3 分以上経過しても確実な進捗や解決の目処が立たない場合、直ちに作業を中断
     してユーザーに状況を報告し、その後の指示を仰ぐこと。
   - 認証情報（API キー等）が見当たらない、あるいは環境の設定不備など、自力での解決が
     困難な「詰まり」が発生した際、独断で深追いしてユーザーの時間を浪費することを
     厳禁とする。

## テスト設計規範 (Testing Standards Compliance)

AI エージェントは、テストコードを作成・修正する際、以下の「仕様が染み出るテスト」の
原則を必ず守ること。

1. **AAA 形式の遵守**:
   - `Arrange`（準備）、`Act`（実行）、`Assert`（検証）のセクションを明確にコメントで
     分けること。
2. **ログによる成功の証明**:
   - `t.Logf` を用い、「何を期待して、その結果どうであったか」を日本語で肯定的に記録
     すること。
3. **テスト対象の明示**:
   - 各テストファイルの冒頭に、標準形式の「テスト対象情報」注釈を記述し、紐付けを
     明確にすること。
4. **ソースコード改変の原則**:
   - テスト作成・整備フェーズにおいては、合意された範囲外のソースコード（ロジック）の
     改変を厳禁とする。リファクタリング等はテスト整備完了後、別途相談・合意の上で
     実施すること。
5. **既存日本語コメントの継承**:
   - ソースコード内の既存の日本語コメントは、ドメイン知識を含む資産として「原則維持
     （削除・変更不可、追記のみ可）」とすること。
   - AI の独断で「より正確だと思われる技術用語」への書き換えを行わないこと。
6. **詳細ガイドの参照**:
   - 具体的な記述スタイルや例については、必ず
     [docs/development/TESTING_STANDARDS.md](../docs/development/TESTING_STANDARDS.md)
     を事前に読み、その作法に従うこと。実例は
     [internal/scaffold/rename_test.go](../internal/scaffold/rename_test.go)。
