# コミットメッセージ規約

コミットメッセージから変更履歴（リリース台帳・機能一覧）を半自動生成できるように、
以下の規約に従う。

## 1. 基本形式

```text
<type>: <チケット> <件名>
```

### type (必須)

| type | 用途 | 変更履歴での扱い |
|---|---|---|
| `feat` | エンドユーザーに見える新機能・機能強化 | **機能追加** |
| `fix` | バグ修正 | **バグ修正** |
| `refactor` | 振る舞いを変えない内部リファクタ | **内部改善** |
| `perf` | 性能改善 | **内部改善** |
| `style` | UI 微調整（色・余白・配置等で機能不変のもの） | **内部改善** |
| `docs` | ドキュメントのみ | **運用整備** |
| `chore` | ビルド・スクリプト・設定等 | **運用整備** |
| `test` | テスト追加・修正 | 変更履歴には載らない |

### チケット (推奨)

該当する課題があれば必ず件名に含める。

- **形式**: 【要記入】課題管理ツールのキー（例: Backlog `PROJ-123`。ハイフン区切り、
  大文字、ゼロパディングなし）
- **複数チケット**: `PROJ-133/-134` のようにスラッシュ + ハイフン省略形
- **チケット無し**: 独立した小修正は省略可

### 件名

- 日本語可、命令形寄りで簡潔に
- 件名 1 行で 100 文字以内を目安

## 2. 例

### Good

```text
feat: PROJ-139 業務一覧からのファイル連結グラフ画面を追加
fix: PROJ-137 ガントで子バーが描画されないバグを修正
fix: PROJ-133/-134 最小実行時間フィルタとツールチップ位置のバグ修正
chore: PROJ-132 未使用資産抽出スクリプトを scripts/unused_assets_survey/ に追加
style: ダッシュボードのヘッダーを削除し更新ボタンをフィルターバーに移設
docs: 環境セットアップマニュアルを新規追加
```

### Bad (避けるべきパターン)

```text
update                                  ← type なし、何の変更か不明
fix bug                                 ← チケットも対象も不明
[Fix] PROJ-131 ほか: 5月リリース向けバグ修正・機能更新まとめ
                                        ← 複数の独立した変更を 1 commit にまとめると履歴化が困難
```

## 3. 書き方（文字化け対策）

- 日本語メッセージは `-m` で渡さず、`temp/` の UTF-8（BOM なし）ファイルから
  `git commit -F` で渡す（手順は
  [git_commit_push](../../.agent/skills/git_commit_push/SKILL.md)）
- AI エージェントが作成したコミットには `Co-Authored-By:` トレーラを付け、履歴から
  関与を追えるようにする。値は各エージェントの規定値を使う

## 4. 分割とマージ方式

- 複数のチケットにまたがる大きな変更は**チケット単位でコミットを分割**する
- PR をまとめてマージする場合は、squash ではなく **rebase merge** を推奨する（履歴を
  個別チケット粒度で生成できるため）
- リリース運用（台帳・事前周知・タグ付け）は【要記入】プロジェクトごとに定め、本書から
  リンクする
