# Git 管理外ディレクトリのサブフォルダ命名規約 (data / temp / output)

`.gitignore` 対象の 3 ディレクトリ（`data/` `temp/` `output/`）直下に作るサブフォルダの
命名規約。名前だけで **いつ（日付）→ 何のチケットで → 何を** が読み取れることを目的と
する。一時ディレクトリの置き場・昇格/削除の運用ルールの正典は
[AGENTS.md](../../AGENTS.md) で、本書は「名前の付け方」だけを定める。

## 1. 基本形

```text
<YYYYMMDD>_<チケット>_<内容>    … 対応チケットが 1 つに定まるとき
<YYYYMMDD>_<内容>               … チケットが無い / 複数にまたがり主が決まらないとき
```

| 要素 | 規則 |
|---|---|
| `YYYYMMDD` | 先頭固定・8 桁・区切りなし。`data/` は**受領日**、`temp/` は**作業開始日**、`output/` は**作成（提出）日** |
| チケット | 【要記入】チケットキーの小文字・区切りなし表記（例: Backlog `PROJ-123` → `proj123`）。ブランチ名 `fix/proj123-…` と同じ表記にする。複数チケットにまたがる場合は主チケット 1 つだけを書き、残りは内容語か `README.md` に逃がす |
| 内容 | 日本語でよい（例: `API調査`）。`data/` は受領物の名称をそのまま。**個人名は入れない**（受領者・参加者名は役割語に置換） |

例:

```text
temp/20260914_proj123_API調査/            # 2026-09-14 着手・PROJ-123
temp/20260914_週次レビュー/                # チケット無し
data/_extracted/20260901_受領資料一式/     # 2026-09-01 受領 ZIP の展開物
output/20260930_調査報告/                  # 2026-09-30 作成の提出物
```

日付順に `ls` するだけで時系列に並び、チケット表記で grep すればチケット単位に集まる。

## 2. 文書ファイルの名前

`output/` に置く提出用文書は `<日本語名>_<YYYYMMDD>.<拡張子>` とする
（例: `調査報告_20260930.docx`）。フォルダは日付が先頭、文書は日付が末尾、と覚える。

## 3. 例外: ツールが既定パスで参照するルート

CLI・スクリプト・手順書が既定値として参照するディレクトリは日付を付けず固定名のまま
とし、**その直下**に規約（または各手順書が定める形）を適用する。追加・変更時はこの表を
更新すること。

| ルート | 参照元 | 直下の規則 |
|---|---|---|
| `data/_extracted/` | [CLAUDE.md](../../CLAUDE.md)（受領 ZIP の展開物置き場） | `<受領日>_<受領名>/` |
| 【要記入】 | | |

### 3.1 `temp/` 直下に直置きしてよいファイル（ツール I/O）

ツールがパス直書きで読み書きする、または手順書がその場所を前提にするファイルは
サブフォルダへ移さない。追加時はこの表を更新すること。

| ファイル | 参照元 |
|---|---|
| `temp/commit_msg.txt` | [git_commit_push](../../.agent/skills/git_commit_push/SKILL.md) のコミットメッセージ受け渡し |
| `temp/cmd_diagnosis_<timestamp>.log` | [diagnose_command_failure](../../.agent/skills/diagnose_command_failure/SKILL.md) の診断ログ |

## 4. 運用

- 新規作成時は本規約に従う
- 作業完了時の「昇格 or 削除」判断（[AGENTS.md](../../AGENTS.md)）は従来どおり。日付順に
  並ぶので古いものから棚卸しする
- `temp/` 直下に直置きされた単発ファイル（`.sql` `.log` 等）は対象外だが、同じ作業の
  ものは規約名のサブフォルダにまとめることを推奨する
