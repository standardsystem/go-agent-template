# テスト設計指針 (Testing Standards)

このプロジェクトでは、テストを単なる「コードの検証目的」だけでなく、**「システムの仕様を明証するテクニカルドキュメント」**として位置づけます。
将来の保守担当者（人間およびAIエージェント）がテストを見るだけで仕様を理解できる状態を目指します。

## 標準ルール

### 1. AAA (Arrange-Act-Assert) 形式の徹底

テストの構造を明確にするため、以下の3セクションに分けて記述します。

- **Arrange (準備)**: テストデータの作成、モックの設定、環境変数の準備など。
- **Act (実行)**: テスト対象の関数やメソッドの呼び出し。
- **Assert (検証)**: 期待値と実際の値の比較、副作用の確認。

### 2. t.Logf による「成功」の仕様化

テストが成功した際に、**「何を確認して成功としたか」**を日本語でログ出力します。
これにより、`go test -v` の実行結果がそのまま仕様のチェックリストとして機能します。

### 3. 日本語による文脈（Context）の説明

- **テストコメント**: そのテストが「何を」テストし、「どのような条件で何が起こるべきか」を詳説します。
- **エラーメッセージ**: 失敗時のメッセージも日本語とし、期待値と実測値の差分を具体的に示します。

### 4. テスト対象の明文化 (Test Target Annotation)

各テストファイルの package 宣言直後に以下の形式で注釈を記述します。

```go
// [テスト対象情報]
// 対象ファイル: internal/models/target_file.go
// 対象要素: TargetStruct 構造体、およびその関連メソッド
```

## 運用上の重要原則

- **テスト作成フェーズにおけるロジック改変の禁止**:
  テスト整備中はソースコードのロジックを一切変更しません。不具合発見時はテストで再現させ、修正は別工程とします。
- **既存の日本語コメントの継承**:
  ソース内の既存コメントは原則維持（削除・変更不可）。補足は追記のみとします。
